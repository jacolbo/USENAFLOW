Retoucher “Done X/Y” + Rollover (No PKG/SEL on Retoucher)

Purpose
Manual rollover with a cleaner retoucher UI: hide package/selected counts from retouchers, show Done X/Y, keep “to edit” live, and log the exact number edited on the date it happened. No project cloning. Project is only “Done” when the retoucher presses Mark Done.

Retoucher UI row (per project)
{ClientDisplay} — to edit ({to_edit_remaining}) — done {done_cumulative}/{selected_photos_total} — [Mark Done] / [Rollover]

Hide package_photos and selected_photos from retoucher view.

Keep selected_photos_total internally for the denominator in done X/Y.

ClientDisplay labeling:

1st rollover: {ClientName} (RO)

2nd rollover: {ClientName} (ROAO)

3rd+ rollover: {ClientName} (RO x{rollover_count})

Buttons & Logic

Mark Done

Action: Set status = Done.

Remove row from active schedule immediately.

Log on Project Calendar & Weekly Calendar: “Completed — {done_cumulative}/{selected_photos_total}”.

Rollover

Prompt: “Enter photos completed today.”

Validate:

< 0 → block: “Number can’t be negative.”

> to_edit_remaining → block: “You can’t complete more than remaining.”

Update counters:

day_done = input

done_cumulative += day_done

to_edit_remaining -= day_done

Calendar logging (today):

Weekly Calendar entry: “Edited {day_done} photos — Done {done_cumulative}/{selected_photos_total} (Rollover)”

Project Calendar entry: same text as above.

This explicitly records the amount done on that date.

If to_edit_remaining > 0:

rollover_count += 1, last_rollover_date = today()

Schedule remaining to tomorrow (or next available working day if tomorrow is blocked), same project (no replication).

Keep row visible tomorrow with updated counts and label.

Toast to retoucher:
“You marked {day_done} today. {to_edit_remaining} will roll over to tomorrow (Done {done_cumulative}/{selected_photos_total}).”

If to_edit_remaining <= 0:

Do not auto-complete. Show:
“All photos are complete. Press Mark Done to close the project.”

No rollover scheduled.

Status Rules (hard)

Project remains Not Done/In Progress until Mark Done is pressed.

Never create a new project on rollover (no replication).

Admin/Sales/Lead can still see PKG/SEL elsewhere; retouchers cannot.

Edge Cases

0 entered: allow rollover; log “Edited 0 — Done {done_cumulative}/{selected_photos_total} (Rollover)”.

Capacity conflict tomorrow: queue to the next available working day but still log today’s rollover on both calendars.

Over-entry attempt: block with message and keep focus in input.

Examples (your format)

Start of week (27 selected):
Susan — to edit (27) — done 0/27 — Mark Done / Rollover

After Day 1, retoucher enters 13 and rolls over:
Susan (RO) — to edit (14) — done 13/27 — Mark Done / Rollover

After Day 2, retoucher enters 10 and rolls over again:
Susan (ROAO) — to edit (4) — done 23/27 — Mark Done / Rollover

Calendar Entries (examples)

“Edited 13 photos — Done 13/27 (Rollover)”

2025-08-27 Weekly & Project Calendar:
“Edited 10 photos — Done 23/27 (Rollover)”

Completion day:
“Completed — Done 27/27”
